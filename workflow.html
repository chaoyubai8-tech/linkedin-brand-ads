04

主体制作分两条路线

概念图可以探索审美；真实模型才能提供真实几何与多视角证据。

路线 A · 真实模型

网格 → Blender → 渲染图

取得已有合法 GLB / FBX；必要且已授权时，通过 Tripo Studio 或 API 生成。

  1. 核对输入、模型和来源。
  2. 检查比例、朝向、法线与贴图连接。
  3. 渲染主／侧／背白模及主视角原材质。
  4. 仅采用 status=complete 的渲染记录，仍须目视检查实际图片。

可证明：同一模型的形体、材质和不同观察角度。

Blender 打光不是改进原始网格；白模与材质视图也不自动构成质量提升对照。

tripo-model-showcasetripo-3d / Blender
路线 B · GPT 概念图

原创描述／参考 → 图像生成

适合探索主体、场景与构图，或制作明确披露的概念广告。它没有自动附带对应三维网格。

  1. 使用原创或有授权的参考。
  2. 生成主体并检查结构、边缘和细节。
  3. 标识为 AI concept／概念视觉。
  4. 若要证明真实模型效果，回到路线 A。

可表达：创意意图与视觉方向，不能证明真实生成能力。

AI 白模外观、AI 线框、镜像或变形图片，不是真实三维结构证据。

imagegentripo-ad-art-direction

05

让标题与画面证明同一件事

不是把功能目录塞进一张图，也不是只用一句大标题替代证据。

使用 Skillsad-creative / copy-editingtripo-ad-claimstripo-ad-art-direction
  • Teams：画面需要共享资产、同一工作区或团队管理的关系。几个无关模型不能独自证明团队方案。
  • API：提交、跟踪、成功后获取结果与后续使用要分清；集成示意不能伪装成已完成的客户项目。
  • 图文与站内信：主利益、素材、正文和 CTA 一致。换模型默认不改既有人群、编号、正文、按钮和目的地。
  • 承诺核验：速度、额度、权益、性能或「可直接上线」等表述必须核对当前官方依据，没有证据就收窄或删除。
输入

产出
标题、正文、CTA、画面结构与承诺记录。
验收条件
遮住产品名仍能理解卖点；画面没有暗示未经证实的能力。

本步结论：文案负责说清价值，画面负责解释价值；不能用未经核验的参数或漂亮模型代替产品差异。

09

先记录事实，再形成经验

设计反馈与投放结果是两类证据，不能互相替代。

使用 Skillstripo-ad-learning
  • 审稿阶段记录模型、版式、文案的问题与修改，不把个人偏好写成所有领英用户的规律。
  • 有真实投放数据后，按地区、人群、目标、时间窗口与点击口径比较，保留消耗与样本量。
  • 素材随后按有效线索和实际使用表现筛选；CTR、CPM 等只解释相应环节。
  • 确需沉淀长期规则时，写清旧规则、新规则、证据、适用范围和版本，不自动覆盖云端规则库。
输入
审稿反馈；投放后的广告与线索数据。
产出
有限结论、待验证假设与规则更新提案。
验收条件
结论有范围、有证据，不把点击好称为业务转化最好。

本步结论：目前没有这一轮新稿的投放实验结果。先完成素材与审稿，不能提前宣布效果提升。

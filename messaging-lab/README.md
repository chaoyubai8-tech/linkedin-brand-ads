# Tripo 领英站内信审核稿

独立于历史稿的 Conversation Ads 审阅子站。四组已确认人群与方向不变，每组有三个文案表达版本，共十二版；英文文案与完整中文释义同步。R7 把已核对的产品机制对应到业务问题与项目用途，技术参数后置到回复。Teams 继续站内原生留资预览，API 继续 Quick Start，R5 中英并排卡片布局不变。不是广告后台，不会发送消息、读取领英个人资料或提交表单。

## 使用

从已有项目根目录启动静态 HTTP 服务，再打开 `messaging-lab/index.html`。不要只双击文件：交互需要读取同目录 JSON。无需安装依赖或构建。

- `index.html`、`lab.css`、`lab.js`：原生静态前端。
- `copy.json`：十二版候选、三十六条预设消息、按钮出口、官方发送者确认与 Teams 共用表单文案。
- `research.json`：人群、参考案例、来源和逐项核查状态。
- `all-copy.html`：不依赖脚本的完整双语文字。
- `copy.csv`：带 BOM 的 UTF-8 文案表；含主题、正文、按钮、补充说明及 Teams 表单／确认文案，不含内部创作理由。`leadgen` 的目标列是表单引用 ID，不是假造 URL。

## 审稿逻辑

原定人群 → 文案 A／B／C → 中英版式预览／流程与双语全文。

R7（2026-10-13）根据当前 Teams 销售演示稿和官方产品机制修改实际双语文案：美国 Teams 讲重复制作、文件交接与团队资源；欧洲 Teams 讲角色／道具在游戏项目中的使用；美国 API 讲已有工具处理生成请求；欧洲 API 讲企业内容平台中的产品展示。组内仅主题与开场不同，共享主体、CTA与两条回复相同。36条英文消息均不超过500字符；所有主题不超过60字符、CTA不超过25字符。表单说明同步到资产制作需求；字段、提交后确认和承接流程不变。

这份销售稿提供功能与行业用途，不作为客户节省成本的实绩证明。未采用稿中的制作周期估算、单模型额度折算、产能折算、回本示例或未核实的客户结果。试用建议把生成、重试、人工精修、验收与接入一起评估，未承诺已准备好的指南、案例下载、免费评估报告或无需开发。原稿及私有案例资料不随公开代码发布。

本轮使用 ad-creative 2.8.2、copy-editing 2.0.0 与本地 Tripo workbench／claims 1.0.0。私有规则库读取失败，未宣称云端同步；品牌语言及 L1 全文验收状态仍沿用下述未完成边界。

R6（2026-10-12）把每组开场改为「相关场景 → 产品定位 → 三条具体卖点 → 下一步」，后续回复解释能力如何用于已有项目。美国 Teams：文字／图片生成、HD Model 最高 200 万多边形／Smart Mesh 四边面、PBR、共享积分及资产库；欧洲 Teams：游戏角色与道具、四边面、可选 8K、适用角色绑定与 DCC 衔接。美国 API：程序化生成、面数／四边面、PBR／兼容绑定、GLB 与 FBX；欧洲 API：产品图片／多视角、可选 8K PBR、GLB 与 USDZ、自有产品展示。

此前 R4（2026-10-12）按对外审核需要精简界面：移除内部理由、核对状态、重复说明和历史导航，当时仅做显示调整；R5 已恢复默认版式预览，R6 按用户明确要求更新实际产品卖点文案。内部核对记录保留在版本记录和研究数据中，不再在审核页显示；界面精简不表示品牌与合规验收已完成。

## Teams 留资链路（2026-10-12）

站内信 → 同一张领英原生留资表单 → Tripo 官方团队跟进 → 核实注册邮箱、试用条件与名额。官网入口放在提交后进一步了解，不是强制二次填表。

用户确认 Tripo 官方领英发送者已开通。网站按此展示官方身份；这不等于本次进入后台验证了原生表单、Lead Gen 目标、线索下载权限或 CRM。未创建、激活或测试任何实际广告及表单。

表单文案包含标题、说明、名字、姓氏、工作邮箱、公司、职位、官方隐私政策链接及提交后确认。无必填电话、需求长问答、虚构指南／客户案例或自动开通承诺。正式使用前仍需完成公司隐私与合规审核及实际线索承接。

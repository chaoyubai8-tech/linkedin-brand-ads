# Tripo 站内信工作室

独立于历史稿的 Conversation Ads 审阅子站。四组已确认人群与方向不变，每组有三个文案表达版本，共十二版；英文文案与完整中文释义同步。R3 将 Teams 六版改为站内原生留资方案，API 六版文案保持不变。不是广告后台，不会发送消息、读取领英个人资料或提交表单。

## 使用

从已有项目根目录启动静态 HTTP 服务，再打开 `messaging-lab/index.html`。不要只双击文件：交互需要读取同目录 JSON。无需安装依赖或构建。

- `index.html`、`lab.css`、`lab.js`：原生静态前端。
- `copy.json`：十二版候选、三十六条预设消息、按钮出口、官方发送者确认与 Teams 共用表单文案。
- `research.json`：人群、参考案例、来源和逐项核查状态。
- `all-copy.html`：不依赖脚本的完整双语文字。
- `copy.csv`：带 BOM 的 UTF-8 文案表；含主题、正文、按钮、补充说明及 Teams 表单／确认文案，不含内部创作理由。`leadgen` 的目标列是表单引用 ID，不是假造 URL。

## 审稿逻辑

原定人群与方向 → 文案 A／B／C → 对话预览／路径与全文／表达理由／品牌与上线核对。

分支仅为预设消息。Teams 主 CTA `Discuss a team trial` 打开原生表单模拟；五个字段禁用且为空，不采集、提交或保存资料。`预览提交后页面（不提交）` 只切换到确认文案示例，再次明确“没有提交、没有开通试用”。API 外部按钮先展示目的地，再由审稿人手动打开。Not Interested 是平台系统选项说明，不算自定义按钮，也不导出到文案字段。

每组 A 提问开场、B 直接陈述、C 用途结果开场。仅主题与开场句不同，产品说明、收尾、按钮、两条后续回复与正式目的页相同。人群、主诉求与使用场景固定，不细分岗位、不扩展业务、不提出新策略或预算。十二版是文案数量，不是广告组或同时上线数量；主题与开场同时不同，不宣称是严格单变量实验。再营销和 Before / After 未恢复。

## Teams 留资链路（2026-10-12）

站内信 → 同一张领英原生留资表单 → Tripo 官方团队跟进 → 核实注册邮箱、试用条件与名额。官网入口放在提交后进一步了解，不是强制二次填表。

用户确认 Tripo 官方领英发送者已开通。网站按此展示官方身份；这不等于本次进入后台验证了原生表单、Lead Gen 目标、线索下载权限或 CRM。未创建、激活或测试任何实际广告及表单。

表单文案包含标题、说明、名字、姓氏、工作邮箱、公司、职位、官方隐私政策链接及提交后确认。无必填电话、需求长问答、虚构指南／客户案例或自动开通承诺。正式使用前仍需完成公司隐私与合规审核及实际线索承接。

## 验收边界（2026-10-12）

Studio Context 与视觉规范文字已读；品牌语言仅部分章节已读；L1 合规正文未完整读取。未完成全部品牌与合规验收。

官方发送者已由用户确认开通；实际可投地区与语言、原生 Lead Gen Form、线索访问权限、配图、事件承接和 Campaign Manager 预览需另行验收。配图制作须使用素材中台并核对真实来源和模型证据。当前网站不是已批准上线的广告。

页面不转载内部手册全文、原始案例 PDF、联系人、私有价格表或凭证。对案例只借鉴路径，历史案例表现不是 Tripo 成效证明。代码公开可审阅；品牌、第三方内容与素材权利不因源码公开而被重新授权。

“品牌与上线核对”包含按产品过滤的承诺台账及逐项核验日期，保留条件与禁用推论。R3 重核原生表单要求、隐私链接与试用条件；未改 API 的旧核验日期。它不替代品牌手册全文、L1 合规或实际账户验收。
